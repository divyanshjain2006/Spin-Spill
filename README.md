# Spin & Spill

Real-time Truth or Dare built with React, Express, Socket.IO, MongoDB/Mongoose, and plain JavaScript. The code is deliberately organized into small, readable modules for learning.

## Run locally

1. Copy `.env.example` to `.env`.
2. Set `MONGODB_URI` to a MongoDB connection string if you want rooms to persist between server restarts. Without it, rooms stay in memory for that server session.
3. Run `npm install`.
4. Run `npm run dev`.
5. Visit `http://localhost:5173` in two browsers, create a room, and join with its code.

The authoritative gameplay rules are in `server/src/services/game.js`; Socket.IO events and Express setup are in `server/src/index.js`; built-in prompts are in `server/src/data/prompts.js`.

## Deploy the complete app on Render

This repository includes a `render.yaml` Blueprint. The deployed app serves the built React frontend and the Express/Socket.IO backend from the **same public HTTPS URL**. This avoids needing a separate GitHub Pages frontend URL or configuring a different Socket.IO origin.

1. Create a MongoDB Atlas database if you do not already have one.
2. In Atlas, create a database user and copy the application connection string. Replace its username, password, and database name placeholders. Do not commit this URI to GitHub.
3. In Atlas Network Access, allow connections from Render. For a quick hobby deployment, allowing `0.0.0.0/0` is the simplest setup because free Render services do not have a single fixed outbound IP. Use a strong, dedicated database password and keep the URI private.
4. Open the Render Dashboard and choose **New → Blueprint**.
5. Connect the GitHub repository `divyanshjain2006/Spin-Spill` and select its `main` branch.
6. Render reads `render.yaml`. When prompted for `MONGODB_URI`, paste the Atlas URI through Render's environment-variable form. Do not put it in this file.
7. Create and deploy the Blueprint. Wait for the deployment to complete successfully.
8. Open the generated Render service URL. Check that adding `/api/health` returns JSON with `ok: true` and `database: "connected"`.
9. Share the **same Render URL** with all players. Create a room and test it from at least two separate devices.

### Why this is one service

In production Express serves the static files generated by Vite from `client/dist`, while Socket.IO runs on the same HTTP server. The frontend therefore connects to its current origin automatically. The local Vite proxy remains available for development.

### Hosting notes

- Render free web services can sleep after 15 minutes without traffic; the first visit after sleep may take about a minute to wake up.
- If `/api/health` reports `memory fallback`, the app did not connect to MongoDB. Fix the `MONGODB_URI` or Atlas network access before using the app for a group game.
- The room data is persisted in MongoDB when the connection succeeds. Do not share database credentials or make the database itself publicly accessible.
- GitHub Pages is no longer needed for the deployed version because the Render service hosts both the frontend and the backend.

## Library choices

- React and Vite provide the frontend.
- Express provides HTTP endpoints and serves the production frontend.
- Socket.IO synchronizes room state in real time.
- Mongoose persists room state in MongoDB.
- `qrcode.react` draws the invite QR code.
- Everything else uses React, CSS, and ordinary JavaScript.
